PROJECT · MYSQL

Delivery Management System schema

Challenge
Order tracking, delivery scheduling and reporting all needed one reliable source of truth.
What I did
Designed and optimized the MySQL schema: table structure, relationships and constraints, plus stored procedures and triggers for business rules, data validation and audit trails.
Result
A normalized schema that backs live operations and reporting, part of ~50 tables across DMS and TMS with full referential integrity.
-- example pattern: audit trail trigger
CREATE TRIGGER trg_order_status_audit
AFTER UPDATE ON orders
FOR EACH ROW
  INSERT INTO order_status_log
    (order_id, old_status, new_status, changed_at)
  VALUES
    (NEW.id, OLD.status, NEW.status, NOW());
Simplified example of the trigger pattern
PROJECT · MYSQL

Trailer Management System data model

Challenge
A new system to track trailers, their allocation and their movement, with no existing data model.
What I did
Built the MySQL model from scratch with normalized tables, primary and foreign keys, and constraints that stop bad data at the door.
Result
Clean, consistent trailer data that the backend team builds on directly.
-- example pattern: enforcing relationships
CREATE TABLE trailer_allocations (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  trailer_id  BIGINT NOT NULL,
  depot_id    INT NOT NULL,
  allocated_at DATETIME NOT NULL,
  FOREIGN KEY (trailer_id) REFERENCES trailers(id),
  FOREIGN KEY (depot_id)   REFERENCES depots(id)
);
Simplified example of the modelling approach
PERFORMANCE · QUERY TUNING

Cutting query response time by ~70%

Challenge
Slow queries were holding up applications and reports.
What I did
Read execution plans with EXPLAIN, rewrote heavy joins and subqueries, and added composite and covering indexes where full-table scans were happening.
Result
Query response time down by about 70% on the tuned queries.
Before tuning100%
After tuning~30%

CREATE INDEX idx_orders_status_date
  ON orders (status, delivery_date);

MIGRATION · PYTHON

Moving 500K+ records between clusters

Challenge
Data had to move between databases in the same cluster and across different clusters without loss.
What I did
Wrote Python migration scripts that copy data in batches, then validate and reconcile row counts and values on both sides.
Result
More than 500,000 records migrated, with checks confirming the data matched.
# example pattern: batch copy + reconcile
for batch in read_in_batches(src, size=5000):
    write_batch(dst, batch)

assert count(src) == count(dst), "row mismatch"
assert checksum(src) == checksum(dst)
